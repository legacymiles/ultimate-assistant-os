Built 2026-07-12: **Skills Library** — a private, searchable vault for skill prompts at `/apps/skills-library` in the [[projects-timeline]] Assistant OS hub. Rows show title + overview + an origin badge; click → detail modal with the full markdown prompt in a mono `<pre>` + Copy button. Search + origin filter chips (All / Personal / plugin names). Manual add: paste a `.md`, title/overview auto-fill from `name:` / `description:` frontmatter (`src/lib/skills/parse.ts`), editable.

**Sync from Claude Code** (added same day): server route `src/app/api/skills/scan/route.ts` (nodejs runtime, force-dynamic) reads the user's skill files from disk and returns `{available, skills[]}`. Sources: personal `~/.claude/skills/<name>/SKILL.md` (origin "Personal") + plugin cache `~/.claude/plugins/cache/<mp>/<plugin>/<ver>/skills/<name>/SKILL.md` (origin = plugin). Currently mirrors **48 skills** (6 Personal + vercel 25, superpowers 14, skill-creator 1, imessage 2). The library auto-syncs on open and via a manual "Sync" button; `store.upsertScanned` upserts by `slug` (folder name, or `plugin:name`) so re-sync updates in place — Supabase `.upsert(onConflict:'user_id,slug')` or localStorage merge. Manual skills (slug null) are never touched by sync.

**Key constraint:** the scan reads the local filesystem, so it only works when the app runs **on the user's machine** (local dev). Deployed on Vercel → `available:false`, no-op. Bridge to production: sync locally *while logged in* with Supabase configured → skills land in the `skills` table → deployed site shows them.

**Gotchas hit (don't regress):** (1) plugin path parsing must accept only `.../skills/<name>/SKILL.md` — skip nested `<name>/upstream/SKILL.md` copies and plugin-internal `.claude/skills/` dev skills, else vercel produced 10 duplicate `vercel:upstream` slugs. (2) frontmatter parser must handle YAML **block scalars** (`description: >-` / `|` + indented lines), used by exploded-showcase + 3 plugin skills, else overview shows a literal ">-".

**How to apply:** for cloud/multi-device, run `supabase/skills-library-schema.sql` in Supabase (table `skills` + RLS + `slug`/`source`/`origin` columns + `(user_id, slug)` unique index for upsert). No markdown renderer installed — raw `.md` in a `<pre>` is intentional (ideal for copy-paste). Files: `src/components/skills/` (SkillsLibrary, SkillRow+OriginBadge, SkillDetailModal, SkillEditorModal), `src/lib/skills/` (types, parse, store), registered in `src/lib/catalog.ts` (slug skills-library).

**Featured (built-in) skills — added 2026-07-20:** a third `SkillSource` value `"featured"`. `src/lib/skills/seed-skills.ts` exports `FEATURED_SKILLS: Skill[]` that `store.ts` `listSkills()` merges into BOTH the localStorage and Supabase results via `withFeatured()` (dedupes by slug AND title so a later real sync of the same skill wins, never double-shows). This is how a skill is put "on the website" without Supabase auth — it's baked into the code, so it shows on every browser/deploy (this repo runs **local mode**, no Supabase in `.env.local`, so per-browser localStorage would NOT reach the deployed site). Featured skills are **read-only**: SkillRow hides edit/delete when `source==="featured"`; SkillDetailModal swaps Edit/Delete for a "View on GitHub" link (new optional `Skill.sourceUrl`). `sortSkills` ranks featured first (0), then manual, Personal, plugins.
