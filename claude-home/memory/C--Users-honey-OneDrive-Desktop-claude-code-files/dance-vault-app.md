Dance Vault (`/apps/tiktok-dances`) is a drifting wall of TikTok dances that play
on hover, each with a personal 0–100 score, plus a Dance of the Day added on
autopilot. Part of the OS hub — see [[ultimate-assistant-os-portfolio]].

The decision that shapes everything: **TikTok cannot be hover-autoplayed** (its
embed is an iframe with a play button, CDN URLs are signed and expire), so
**YouTube is the playback source and TikTok is only the credit link**.

Playback ladder per tile: local mp4 (needs `yt-dlp`, NOT installed on this
machine) → hover-mounted YouTube iframe (the day-one path) → poster.

The honesty gate, shared by the seed script, manual adds and the daily pick
(`src/lib/dances/resolve.ts`): YouTube search scrape → keyless oEmbed →
`playableInEmbed` on the watch page. oEmbed alone answers "does it exist", NOT
"will it play in an iframe" — that third stage is what prevents tiles that look
fine and play nothing. The seed is generated by `node scripts/dances-resolve.mjs`
and committed; names that resolve to nothing are dropped.

Gotchas learned building it:
- `loading="lazy"` never fires inside a `width: max-content` track moved by
  transform — every poster stays pending forever. Use eager.
- A model ignores an exclusion list in the prompt; it returned three dances
  already in the seed. Enforce dedupe in code (`src/lib/dances/names.ts`).
- The Claude Browser pane runs hidden with `innerWidth: 0`, so `requestAnimationFrame`
  never fires and rAF-driven motion looks broken. Verify motion with the
  Playwright MCP browser instead.
